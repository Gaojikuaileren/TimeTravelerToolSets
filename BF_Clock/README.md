# BF Clock · 逆行时钟

一台从你第一次打开它的那一刻起，就一直向过去走的时钟。

- 表盘指针逆时针走，数字读数逐秒倒退。
- **关掉网页、关掉电脑，它照样在走。** 隔三天再打开，正好倒退了三天。
- 纯静态：一个 HTML、一个 CSS、一个 JS，没有后端，没有依赖，没有追踪。

## 它怎么做到「关了也继续走」

页面关闭后 JavaScript 就停了，所以计时器（`setInterval` 累加）做不到这件事 —— 那种做法一刷新就归零，还会累积误差。

这里改用**锚点推算**。第一次打开时，把那一刻的真实时间戳记进 `localStorage`，之后每一帧都现算：

```
显示时间 = 锚点 − (此刻 − 锚点) = 2 × 锚点 − 此刻
```

时间是「算」出来的，不是「数」出来的。于是：

- 关多久，回退多久，一秒不差；
- 刷新、切标签页、设备休眠，都不影响；
- 完全不需要服务器来「替你计时」。

## 锚点从哪来

按优先级：

1. URL 上的 `?anchor=<毫秒时间戳>` —— 点「复制带锚点的链接」得到，用来把同一段旅程带到别的设备/浏览器；
2. 本机 `localStorage` 里的存档；
3. 都没有，就以此刻为锚点，开始新的旅程。

锚点存在浏览器本地。换设备、换浏览器、清空站点数据都会重新出发 —— 想留住就用那条分享链接。

## 界面上的东西

| 元素 | 含义 |
| --- | --- |
| 表盘 / 大数字 | 当前的逆行时间 |
| 已回溯 | 从出发到现在，一共倒退了多久 |
| 出发锚点 | 旅程开始时的真实时间 |
| 重设锚点 | 丢弃当前旅程，从此刻重新出发 |
| 复制链接 | 生成带锚点的链接，跨设备接续 |

## 本地预览

双击 `index.html` 就能看。若想用 `?anchor=` 参数，起个本地服务器更稳妥：

```bash
python -m http.server 8000
```

然后访问 <http://localhost:8000/BF_Clock/>。
